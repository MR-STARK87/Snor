### Real PTY resizing — the proof

The previous session's bug was "the rectangle resizes but the PTY does not".
Measured with `$Host.UI.RawUI.WindowSize` inside each pane:

- 2 panes even: both **100x47**
- after dragging the divider right: left **131** cols, right **70** cols
- 4 panes 2x2: all four **100x22**
- after exiting Flow to normal mode: left pane **167x16**

Independent sizes, changed by dragging, and the scrollback (`$PID` 12324,
the earlier `WindowSize` outputs) all survived — the shell process was never
restarted.

### Bug 1 — the cap notice was painted over the first pane's header

`flow_ui` painted `notice` at `rect.min + (8, 2)`, which is exactly where the
first pane draws its focus dot, title and cwd. Refusing a fifth terminal
overlaid "at the 4-terminal limit — close one first" on "powershell
C:\My work folder\Snor" and all three interleaved into unreadable mush at the
moment the user needed to read it. Reproduced at 4 panes, screenshotted.

Fix: `flow_ui` no longer paints it. `Terminal::notice_text()` exposes it and
`app.rs` draws it in the status bar beside the "Flow" word, where nothing can
collide. Normal mode's inline tab-strip notice is unchanged.

### Bug 2 — panes were sized after polling, freezing a torn TUI frame

`apply_size` ran inside `render_pane`, i.e. *after* `flow_ui` had already
called `poll()`. A resize therefore resized the ConPTY after that frame's
output had been drained; the TUI's repaint for the new size only reached the
grid on the next poll, and if the shell then went quiet the half-resized
frame stuck until an unrelated event forced a repaint.

Visible as OpenCode's ASCII logo half redrawn — top half at the new width,
bottom half still the old — frozen for 8+ seconds and unchanged by a forced
Ctrl+L. Reproduced and screenshotted.

Fix: new `Terminal::size_panes(area, cell)` runs **before** `poll()`, so the
output a resize provokes is drained in the same frame it was asked for. It
also subtracts `PANE_HEADER_H` + `PANE_GRID_PAD`, which the renderer's raw
`ui.available_size()` did not — so a shell is no longer told it owns a row
the pane does not actually draw.

`FlowView.cell` became unused and was removed.

### False alarm worth recording

A second "torn frame" turned out **not** to be one. The headless drag had
missed the divider and instead started a text selection inside a pane, which
paints a highlight over the text — at a glance it reads like corruption. If a
drag is meant to grab a divider, confirm the divider's real x first (measure
it out of the screenshot) or the result is a selection, not a resize.

### Hazard: `git checkout main` mid-flight leaves a deleted working tree

The first `git checkout main` was SIGTERM'd partway through, and the result
was dangerous: HEAD reported `main` while the tree was `dev`, and **51 tracked
files showed as deleted, including `src/syntax.rs`**. A commit made in that
state would have wiped them. `git status` was the tell.

- The kill left a zero-byte `.git/index.lock` with no git process alive.
  Cleared it manually after confirming via `tasklist` that nothing was running.
- Recovered with `git checkout -f dev`, then `git checkout -- .`.
- Lesson: after any interrupted git command, check `git status` and confirm
  tracked files still exist on disk before doing anything else.
